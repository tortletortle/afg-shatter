# AFG / 万物粉碎 — V0.17 接触岛预算调度版

V0.17 在 V0.16 持久接触热启动基础上，增加接触岛级窄相预算分配，重点降低多个独立碰撞区域竞争固定 GJK 预算时的饥饿风险。

## V0.17 改动
- 从当前帧候选碰撞对构建连通接触岛。
- 按岛内最高碰撞优先级、候选对数量和等待时间计算预算权重。
- 将全局 GJK 单元对测试预算分配给各接触岛；预算足够时每岛至少获得一个测试额度。
- 当接触岛数量超过预算时，先按优先级分配服务槽，并用等待时间老化机制提升长期未获预算岛的优先级。
- 岛内候选对按碰撞分数排序；每个岛的测试不超过该岛额度，且不超过全局剩余预算。
- 未获得预算或岛预算耗尽的候选对使用既有保守球形回退路径。
- 增加接触岛数、已服务岛数、岛预算实际使用量和预算回退遥测。
- 增加帧间隔 P95/P99、物理步耗时 P95/P99 显示。

## 运行
- `index.html`：优先 WebGL2，失败时回退 Canvas2D。
- `compat.html`：强制 Canvas2D。
- Windows 双击 `start.bat`。
- ChatGPT 内置预览可能限制页面脚本，请解压后使用独立 Edge / Chrome 打开。

## V0.17 调度器压力测试
- 100 / 300 / 500 / 1000 个合成碎片图规模均通过。
- 对应候选边数：87 / 262 / 437 / 875。
- 合成接触岛数：13 / 38 / 63 / 125。
- 每组固定预算 900，分配总量均精确为 900，所有岛均获得预算。
- 单元测试覆盖：总预算守恒、单岛额度、岛数超过预算、等待时间老化防饥饿。
- WebGL-first 与 Canvas2D 构建的调度器结果一致。
- 两个构建各 6 个内联脚本块通过语法编译。

## 重要验证边界
100/300/500/1000 是合成连通图上的调度器规模测试，不是 1000 个真实碎片的物理仿真测试，也不构成浏览器 FPS 或 P95/P99 性能结论。当前运行时容量仍为 MAX_BODIES=100、MAX_CELLS=180；本版没有擅自提高容量上限，因为扩大上限前需要真实设备性能和内存测试。

帧间隔 P95/P99 是 requestAnimationFrame 采样的帧间隔；物理步 P95/P99 是物理求解函数的耗时采样。两者均需在目标设备真实运行后才有实际性能意义。
